# 작업 지시: Oxford 3000 학습 데이터 제작

이 문서는 단어 데이터 제작 담당(Codex)을 위한 작업 지시서다. 배경은 [functions.md](functions.md), 데이터 구조와 파이프라인 전체는 [development_plan.md](development_plan.md) 3장을 참고한다.

## 1. 목표

Oxford 3000 단어 전체에 대해 한국어 뜻과 예문 3개(영어 + 한국어 번역)를 만들어 `data/levels/{a1,a2,b1,b2}.json`에 저장한다. 앱 코드는 수정하지 않는다.

## 2. 작업 범위

**수정 가능**
- `data/source/oxford3000.csv`
- `data/levels/*.json`

**수정 금지**
- `src/`, `scripts/`, `docs/`, 설정 파일 전부
- `src/data/words.json` (앱 쪽에서 등급 완료 시 병합한다)

검증 스크립트(`scripts/build-data.mjs`)에 문제가 있다고 판단되면 고치지 말고 보고한다.

## 3. 브랜치

- `data` 브랜치에서 작업한다. `main`에 직접 커밋하지 않는다.
- 한 등급이 끝날 때마다 보고하면 앱 쪽에서 `main`로 병합한다.

## 4. 작업 순서

### 4.1 원본 목록

`data/source/oxford3000.csv`를 만든다.

```csv
word,pos,cefr
a,indefinite article,A1
about,preposition;adverb,A1
```

- 열: `word`, `pos`, `cefr`. 품사가 여러 개면 `;`로 구분해 한 줄로 합친다.
- 같은 단어가 품사별로 다른 등급이면 **가장 낮은 등급**을 쓴다.
- 정렬: 등급(A1 → A2 → B1 → B2), 등급 안에서 알파벳순. (완료: 공식 PDF에서 변환 후 미국식 철자로 바꿨다. 등급 파일은 이 CSV 순서를 따르고, 앱의 Unit 배치는 병합 시 `build-data.mjs`가 등급 안에서 섞는다.)
- 공식 목록에 접근할 수 없으면 작업을 멈추고 보고한다. 기억에 의존해 목록을 만들지 않는다.

커밋: `data: add oxford3000 source list`

### 4.2 등급별 생성

CSV 순서대로 **100단어씩** 생성해 해당 등급 파일 끝에 추가한다. 등급 파일은 `Word[]` JSON 배열이며 **한 줄에 항목 하나** 형식으로 쓴다(아래 예시는 보기 좋게 펼친 것).

파일은 편집 도구로 직접 쓴다. `node -e`·셸 echo로 JSON을 만들면 예문의 아포스트로피 때문에 깨진다.

```json
{
  "id": "run",
  "word": "run",
  "pos": ["verb", "noun"],
  "cefr": "A1",
  "meanings": ["달리다", "운영하다", "달리기"],
  "examples": [
    { "en": "I run in the park every morning.", "ko": "나는 매일 아침 공원에서 달린다." },
    { "en": "She runs a small coffee shop downtown.", "ko": "그녀는 시내에서 작은 커피숍을 운영한다." },
    { "en": "Let's go for a run after work.", "ko": "퇴근하고 달리기하러 가자." }
  ]
}
```

필드 규칙:

| 필드 | 규칙 |
|---|---|
| `id` | `word`의 소문자. 공백은 그대로 둔다 (`"ice cream"`) |
| `word`, `pos`, `cefr` | CSV 값 그대로. `pos`는 배열 |
| `meanings` | 1~3개. 가장 흔한 뜻이 첫 번째. 사전식 짧은 표현(문장 금지). 품사가 여러 개면 주요 품사마다 하나 이상 |
| `examples` | 정확히 3개. 아래 예문 규칙 참고 |

### 4.3 예문 규칙

- **일상회화 중심.** 친구, 가족, 직장, 쇼핑, 여행처럼 실제로 쓸 만한 상황.
- **3개가 서로 다르게.** 다른 상황, 다른 뜻 또는 다른 품사, 다른 문장 형태(평서문, 의문문, 명령문 등)를 섞는다.
- **대상 단어가 반드시 포함.** 변화형(runs, ran, running)은 허용.
- **길이:** 6~14단어. A1·A2는 짧고 쉽게, B1·B2는 조금 더 길어도 된다.
- **어휘 수준:** 대상 단어 외의 단어는 `oxford3000.csv`에서 그 단어와 같거나 낮은 등급에 있는 단어를 우선 쓴다. 목록 밖 단어는 기본 기능어(the, is, to 등)와 아주 쉬운 단어만 허용한다.
- **표기:** 미국식 철자. `oxford3000.csv` 표제어도 미국식으로 변환되어 있다(color, center, favorite, gray, meter, mom 등). 사람 이름·브랜드명·숫자 남발 금지.
- **피할 내용:** 정치, 종교, 폭력, 선정적 내용, 특정 집단에 대한 고정관념.
- **한국어 번역:** 직역보다 자연스러운 구어체. 반말/존댓말은 문장 상황에 맞추되 한 예문 안에서 섞지 않는다.

### 4.4 검증

100단어를 추가할 때마다 실행한다.

```
node scripts/build-data.mjs --check
```

- 오류가 있으면 고친 뒤 커밋한다. 오류가 남은 상태로 커밋하지 않는다.
- "예문에 단어 없음" 경고는 해당 예문을 다시 확인하고, 불규칙 변화형이라 문제없으면 그대로 둔다.
- 커밋 전에 방금 만든 100단어 중 10개 이상을 직접 읽고 뜻·번역이 어색하지 않은지 확인한다.

## 5. 커밋 규칙

**100단어 = 커밋 1개.** 여러 배치를 한 커밋에 섞지 않는다.

Codex 샌드박스는 git 쓰기가 막혀 있으므로 **Codex는 파일 생성·검증까지만 하고, 검토와 커밋은 Claude가 한다.**

```
data(a1): words 1-100
data(a1): words 101-200
...
data(a1): words 801-857 (level complete)
```

- 숫자는 해당 등급 안에서의 순번이다.
- 등급 마지막 커밋에는 `(level complete)`를 붙인다.
- 기존 항목 수정은 별도 커밋으로: `data(a1): fix examples for "bank", "fair"`
- 커밋 본문에 검증 결과 경고 개수와 확인한 내용을 한두 줄로 적는다.

## 6. 진행 순서와 보고

1. 원본 CSV → 커밋 → 보고 (등급별 단어 수 포함)
2. A1 전체 → 등급 완료 보고
3. 앱 쪽 확인 후 A2 → B1 → B2 순서로 같은 방식 진행

등급 완료 보고에 포함할 것: 단어 수, 커밋 범위, 남은 경고 목록, 판단이 애매했던 단어.
